# Visible State

The visual language makes a process inspectable. Large, quiet fields give each action room; precise boundaries let a viewer follow a relationship without searching for a legend. Alignment carries the structure. Every crop and interval should feel carefully chosen.

Dark ink supplies the ground, slate separates working surfaces, and amber marks a deliberate choice. Green appears where the underlying record supports a completed state. Color carries meaning before it carries decoration; the palette stays small enough to remember.

Scale directs attention from a name to an action to its evidence. Generous headings remain legible in a gallery preview, while close views preserve the important details of the actual interface. The compositions require meticulous control of edge spacing and type rather than additional ornament.

IBM Plex Sans supplies a clear human voice. IBM Plex Mono gives amounts and protocol references an orderly rhythm. Captions stay short and separate from captured interface text, so an explanation cannot be mistaken for a product state.

The craft depends on what is retained. Original captures remain identifiable, data stays intact, and frames reveal only the relevant portion of a larger screen. A second review checks the final raster, with particular care for readable action labels, uncut values, and the distinction between a prepared state and a verified result.

This submission set uses the accepted Bitcoin Sandbox interface. The 20,000-sat happy path and the separate 10,000-sat recovery test are labeled explicitly. All amounts are valueless regtest coins, and the work describes builder-controlled verification.
